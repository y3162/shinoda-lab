# Audio Mamba: 音声表現学習のための双方向状態空間モデル

Mehmet Hamza Erol, Arda Senocak, Jiu Feng, Joon Son Chung

## 概要

Transformer は CNN ベースの手法を上回り、音声分類において急速に主要な選択肢となっている。しかし、Audio Spectrogram Transformer (AST) は self-attention に起因して計算量が二次的に増加する。この二次的な self-attention コストを取り除くことは、魅力的な研究方向である。近年、Mamba のような State Space Model (SSM) は、言語および画像タスクにおいてこの観点から有望な結果を示している。

本研究では、音声分類タスクに self-attention への依存が本当に必要なのかを検討する。そのために、音声分類向けとして初の self-attention を用いない、純粋に SSM に基づくモデルである Audio Mamba (AuM) を提案する。AuM を 6 種類の異なるベンチマークを含む複数の音声データセットで評価した結果、確立された AST モデルと同等、あるいはそれを上回る性能を達成した。コードは `Audio-Mamba-AuM` として公開されている。

## 1. はじめに

近年、deep learning においては大きなパラダイムシフトが起こり、CNN [15, 18] は Transformer ベースのアーキテクチャ [7, 10, 26, 27] に置き換えられつつある。Transformer は convolutional neural network を上回る性能を示すだけでなく、従来はまったく異なるモデルを利用していた多数の研究分野やタスクに対して、統一的なアーキテクチャを提供するという点でも大きな進展をもたらした [1, 2, 11, 12, 21, 23, 24, 29, 30]。

一方で、Transformer は計算負荷の大きい self-attention mechanism に依存している。Attention の計算コストは $O(n^2)$ であり、長い系列を処理する際には自然に問題となる。この制約から、State Space Model (SSM) [8, 13, 14, 25]、特に Mamba [13] のような代替アーキテクチャが注目されている。Mamba は self-attention を置き換え、時間変化するパラメータを導入することで global context を効率的に捉える。Mamba [13] は学習時・推論時の双方でモデル効率を大きく改善し、Transformer ベースの手法に対する有力な代替案となる可能性を示している。Transformer が多様なタスクに対して持つ汎用性・スケーラビリティを考えると、計算効率にも優れる Mamba は、同様に汎用的かつ柔軟なアーキテクチャとなる可能性がある。

Mamba は言語モデリングや画像分野 [19, 20, 31–33] で近年成功を収めているが、Mamba や類似の SSM ベースモデルを音声分類へ適用する研究は、依然として十分に探索されていない。このギャップを埋めるため、本研究では音声スペクトログラムへ直接適用する新しい SSM ベースモデル Audio Mamba (AuM) を提案する。本手法は self-attention を一切用いず、State Space Model のみによる長系列モデリングに焦点を当てる。

AuM は、代表的な音声分類手法である Audio Spectrogram Transformer (AST) [10] と同等の性能を達成するだけでなく、可変長系列を処理できることや他タスクへ転移しやすいことなど、Transformer ベースモデルの利点も維持している。State Space Model を用いることで self-attention への依存を排除し、系列長および特徴次元に対して線形な時間計算量で動作できる。これは二次計算量を持つ AST と対照的である。

本研究に最も近い研究は Vision Mamba [33] である。Vision Mamba は、global visual context のモデリングに bidirectional SSM を利用し、位置情報には positional embedding を用いることで、Vision Transformer (ViT) [7] と類似した構造を採用している。AST が ViT の考え方を音声分類へ適用して成功したことを踏まえ、本研究でも Vision Mamba の知見を参考にし、bidirectional State Space Model を音声分類へ適用するための方法を検討する。具体的には、以下の処理を行う。

1. 入力スペクトログラムを patch に分割し、各 patch を patch embedding token へ射影する。
2. 学習可能な classification token を patch token 列の中央へ追加する。
3. Audio Mamba Encoder block が SSM module を用いて token 列を forward・backward の両方向から処理する。
4. Classification token を supervised audio classification task の学習に使用し、推論時の予測にも利用する。

本研究の貢献は以下のとおりである。

- 音声スペクトログラムを処理する Audio Mamba (AuM) を提案する。AuM は Audio Spectrogram Transformer (AST) に似た構造を持ちながら、bidirectional State Space Model (SSM) を用いて token を forward・backward の両方向から処理する。
- Self-attention module を除去することで、AuM は長い音声系列に対してリソース消費量が線形に増加する性質を持つ。
- AudioSet [9]、AudioSet Balanced、VGGSound [4]、VoxCeleb [22]、Speech Commands V2 [28]、Epic-Sounds [17] の 6 種類のデータセットを用いた包括的な実験により、AuM が代表的な音声分類手法 AST と同等、あるいはそれ以上の性能を達成することを示す。

## 2. Audio Mamba

### 2.1. アーキテクチャの処理フロー

Figure 1 に示す Audio Mamba (AuM) のアーキテクチャでは、まず入力音声波形を音声スペクトログラム

$$
X \in \mathbb{R}^{F \times T}
$$

へ変換する。ここで $F$ と $T$ は、それぞれ周波数方向と時間方向の次元を表す。

スペクトログラムを $N$ 個の正方形 patch からなる系列

$$
S \in \mathbb{R}^{N \times p \times p}
$$

へ分割する。$p$ は各 patch の一辺の長さであり、patch 数 $N$ は

$$
N = \left(\frac{F}{p}\right) \times \left(\frac{T}{p}\right)
$$

で計算される。

各 patch $S_i$ は一次元ベクトル

$$
S_i \in \mathbb{R}^{p^2}
$$

へ flatten され、線形射影によって $D$ 次元空間へ埋め込まれ、

$$
E_i \in \mathbb{R}^{D}
$$

を得る。この処理は patch embedding layer によって実行される。

その後、学習可能な特別な classification token

$$
\mathrm{CLS} \in \mathbb{R}^{D}
$$

を token 列の中央に挿入し、拡張された embedding sequence

$$
E \in \mathbb{R}^{(N+1) \times D}
$$

を構成する。さらに、系列内の各要素の位置を符号化するため、学習可能な positional embedding

$$
P \in \mathbb{R}^{(N+1) \times D}
$$

を加え、token sequence

$$
T \in \mathbb{R}^{(N+1) \times D}
$$

を得る。

この token sequence は $L$ 個の block を積層した Audio Mamba Encoder へ入力される。各 block は入力と同じ次元数を維持するため、encoder は $T$ を

$$
T' \in \mathbb{R}^{(N+1) \times D}
$$

へ変換する。最終的に、更新された classification token の表現 $T'_{N/2}$ が classification head へ入力される。

### 2.2. アーキテクチャ詳細

汎用的なアーキテクチャとなることを目指し、AuM は AST [10] といくつかの共通点を持つ。一方、AuM は self-attention-free model を実現するために、独自の構成要素と設計上の選択を導入している。

#### 事前知識

State Space Model (SSM) は、時間依存の $D$ 次元入力系列 $x(t)$ を出力 $y(t)$ へ写像する連続系を、hidden state $h(t) \in \mathbb{R}^{N}$ を保持することでモデル化する線形時不変系である。この系は次式で表される。

$$
\begin{aligned}
h'(t) &= Ah(t) + Bx(t), \\
y(t) &= Ch(t).
\end{aligned}
\tag{1}
$$

ここで、

$$
A \in \mathbb{R}^{N \times N}, \qquad
B \in \mathbb{R}^{N \times D}, \qquad
C \in \mathbb{R}^{D \times N}
$$

である。

Deep learning algorithm へ適用するため、連続パラメータ $A$ と $B$ に離散化を施し、それぞれ $\bar{A}$ と $\bar{B}$ へ変換する。これらを用いると、離散化された系は次式となる。

$$
\begin{aligned}
h_t &= \bar{A} h_{t-1} + \bar{B}x_t, \\
y_t &= Ch_t.
\end{aligned}
\tag{2}
$$

このような線形時不変系は、linear recurrence と global convolution のどちらとしても計算でき、効率的な処理が可能である [13]。一方、時間不変のパラメータ化を用いるため、特定種類のデータをモデル化する際には限界がある。

Mamba は、この時間不変パラメータを time-variant な形式へ変換することで既存の SSM を拡張し、時間変化する入力から効率的にパラメータを導出できるようにする。具体的には、Mamba block の Forward SSM module（Figure 1(a)）において、まず入力系列

$$
x \in \mathbb{R}^{L \times D}
$$

を Forward Conv1D で畳み込む。その後、式 (2) の時間不変パラメータ $A$, $B$, $\Delta$ を、系列内の各要素 $x_i$ に対応する $A'_i$, $B'_i$, $\Delta'_i$ へ変換する。

Mamba は、入力系列を先頭から末尾まで単方向に処理する、現代的な hardware-oriented scanning method を用いてこれらのパラメータを利用する。詳細は [13] を参照されたい。この仕組みにより、変換されたパラメータを通して入力系列から関連情報を取り込みながら、hidden state を選択的に更新できる。

#### Bidirectional Mamba Encoder

Mamba の単方向 scan は causal sequential data のモデリングには有効であるが、2D data の学習では複数方向から処理することが有益である [19, 32, 33]。例えば画像データを扱う Mamba ベースの ViM [33] は、元の Mamba block（Figure 1(a)）を Figure 1(c) の形へ変更し、特徴抽出方向として Backward Conv1D、または scanning direction として Backward SSM を追加することで、多方向かつ spatial-aware な処理を可能にしている。

同様に AuM は、Figure 1(b) に示す設計を採用し、元の Mamba block に backward scanning direction を追加する。この方法では、同一の convolution feature を利用しつつ、forward SSM と backward SSM の双方でパラメータを time-variant、すなわち input-dependent な形式へ変換して scanning を行う。ViM と同様に、これによって AuM は global context を spatial-aware にモデル化でき、Transformer の self-attention が global context をモデル化する機能を模倣する。

#### Classification Token

純粋な Transformer は入力系列に対して permutation invariant である。一方、AuM block では feature extraction を行う Conv1D と SSM の双方が入力順序に依存するため、入力系列の順序に敏感である。そのため、scanning direction に加えて classification token を入力系列内のどこへ配置するかが学習過程において重要となる。

ViM と同様に、AuM は patch embedding layer の直後、入力系列の中央へ classification token を配置する。この設定は bidirectional processing において性能向上を示しており、ViM および Section 3 の ablation study でも確認されている。

## 3. 実験

### 3.1. データセットと評価指標

#### データセット

実験では、(1) AudioSet Full / Balanced、(2) VGGSound、(3) VoxCeleb、(4) Speech Commands-V2、(5) EPIC-SOUNDS を用いる。

AudioSet [9] は、多様な音声サンプルとそれぞれに付与された複数ラベルを含む大規模データセットである。527 種類のラベルを持ち、10 秒の音声 clip を 200 万件以上収録している。Balanced set は full set から構成された約 20K サンプルのデータセットである。

VGGSound [4] は、各 10 秒の video clip 約 20 万件からなり、309 種類の多様な sound category が付与されている。

VoxCeleb [22] は人間の発話の audio-visual representation に焦点を当てたデータセットで、1,251 人の speaker と約 145K の speech instance を含む。

Speech Commands-V2 [28] は、約 105K 件の 1 秒音声から構成され、広く利用される 35 種類の speech command を含む。

EPIC-SOUNDS [17] は EPIC-KITCHENS-100 [6] の一部であり、egocentric video から切り出した 75.9K の audio segment で構成される。44 class のラベルを持ち、物体同士の衝突など、音によって識別可能な action に焦点を当て、material annotation も含んでいる。

#### 評価指標

AudioSet では 1 サンプルに複数ラベルが存在するため、mean average precision (mAP) を用いる。それ以外のデータセットでは各サンプルが単一ラベルを持つため、top-1 classification accuracy (Acc.) を用いる。

### 3.2. 標準ベンチマークにおける AST との比較

本節では、Audio Mamba (AuM) と Audio Spectrogram Transformer (AST) を比較する。両モデルとも base backbone、すなわち AuM-B/16 と AST-B/16 を使用する。公平な比較のため、実装詳細で説明するように、AST と同一の学習・実験設定を用いる。詳細は Section 5 に示す。

この実験では、AuM と AST のどちらにも他モデルの pretraining weight を利用していない点に注意が必要である。AST の原論文 [10] では ImageNet で pretrain された Vision Transformer (ViT) の weight で初期化されるが、本実験では 2 つの異なるアーキテクチャを純粋に比較するため、それを使用しない。

各実験は同一設定で random seed のみを変えて 3 回実行し、その平均値と標準偏差を Table 1 に示す。提案する AuM は、この実験設定では全体としてより良い性能を達成している。これは、AuM が self-attention に依存せず、より高い計算資源効率を持ちながら、AST に代わる有力な選択肢となり得ることを示している。

**Table 1. AST と AuM の base model を from-scratch で学習した場合の各データセットにおける結果。括弧内は AST に対する差分。**

|---|---:|---:|---:|---:|---:|---:|
| AST-B/16 | 29.10 ± 0.07 | 10.41 ± 0.32 | 37.25 ± 0.31 | 22.44 ± 0.19 | 85.27 ± 1.07 | **44.76 ± 0.20** |
| AuM-B/16 | **32.43 ± 0.31 (+3.33)** | **13.28 ± 1.07 (+2.87)** | **42.58 ± 0.28 (+5.33)** | **28.34 ± 3.38 (+5.90)** | **91.58 ± 3.17 (+6.32)** | 44.17 ± 0.58 (-0.60) |

### 3.3. 効率の観点からの AST との比較

Transformer ベースの音声分類モデルは、特に長い音声や高次元データを扱う場合、二次計算量のため計算負荷が大きい。一方、SSM ベースモデルは計算量と memory efficiency の点で優れている。本節では AuM と AST の効率を比較する。実験には 1 枚の A6000 GPU を使用した。

各 token 数に対応する長さの音声をモデルへ入力し、処理速度と GPU memory consumption を比較した。結果は Figure 2 に示されている。AuM は計算効率・memory efficiency の双方で明確な優位性を示す。

例えば、20 秒の音声、すなわち 1024 token を用いて学習する AuM-Base は、AST-Small と同程度の GPU memory しか消費しない。また、AuM-B は 80 秒の音声でも学習できる一方、AST-B は 20 秒の音声を用いる設定ですでに out of memory となる。

さらに、4096 token における推論では AuM は AST より 1.6 倍高速であり、token 数が増加するほどその差も拡大する。これらの結果は、AuM の計算量が系列長に対して線形に増加する傾向を示している。

### 3.4. 設計選択に関する Ablation Study

設計上の選択を検証し、さらに分析するため、一連の実験を行う。SSM module と Conv1D の方向に関して、以下の 3 種類の戦略を検討する。

**AuM-ForwardConv1D-ForwardSSM:** Default の Mamba block に相当する。AuM block に forward SSM のみを適用する（Figure 1(a)）。

**AuM-ForwardConv1D-BiDirectionalSSM:** 最終的な AuM で採用する設計である。上記の構成に backward SSM を追加する（Figure 1(b)）。

**AuM-BiDirectionalConv1D-BiDirectionalSSM:** Backward direction にもう 1 つ Conv1D を追加し、その出力を backward SSM へ入力することで、各 SSM module を独立した stream とする。Vision Mamba (ViM) ではこれに類似した設計が default として用いられている（Figure 1(c)）。

さらに、各 variant について class token の位置も ablation する。計算時間とリソースを節約するため、主に AudioSet Balanced (AS-20K) と VGGSound でモデルを学習して ablation study を行う。結果を Table 2 に示す。

#### Bidirectional SSM の影響

SSM module の方向性の影響を理解するため、異なる scanning direction を持つ variant の性能を比較する。結果から、forward SSM と backward SSM を併用する bidirectional variant は、forward-only variant より全体的に良い性能を示し、特に大規模な VGGSound でその差が大きい。

#### Conv1D の方向の影響

AuM-Fo-Bi と AuM-Bi-Bi の 2 種類の bidirectional method に対して controlled experiment を行う。両者の唯一の違いは backward Conv1D の有無である。Table 2 に示すように、backward Conv1D を省略する本研究の設計の方が、全体としてより良い性能を示す。

著者らは、forward Conv1D の出力という単一の入力系列を forward・backward の両方向から scan して context 全体を理解する方が、各 directional SSM module に別々の入力を与え、それぞれ一方向のみに scan させるよりも効果的かつ自然であると仮説を立てている。

#### Class token の位置の影響

広範な実験により、本研究の設計では class token を系列中央に配置することが最も適していることが分かった。ただし、class token の位置は非常に重要な設計選択であり、variant ごとに最適な位置は異なり、性能にも大きな影響を与える。

また、forward-only SSM では class token を系列先頭、すなわち head に配置すると性能が崩壊することも観察された。これは期待される結果であり、class token より後ろに存在する系列情報を class token へ取り込めないためである。

### 3.5. Pre-Training の影響

#### Out-of-domain pre-training

ImageNet の pre-trained weight で音声モデルを初期化することは、音声分類で一般的になっている [5, 10]。特に AST は、Supervised ImageNet で pretrain された ViT model の weight を利用することで、from-scratch 学習と比較して大幅な性能向上を示す。

Table 1 の主結果では、2 つのアーキテクチャを明確に比較するため、pretraining による weight initialization を除外している。しかし、AST に利用できる ViT weight に相当する公開済み Vision Mamba Base model weight は、著者らの知る限り存在しないため、同条件でこの実験を直接行うことはできない。

そこで out-of-domain pre-training weight で初期化した AuM と AST を比較するため、利用可能な唯一の Vision Mamba model である small-size の ViM-S を用い、AuM-S と AST-S を比較する。Section 2 および 3.4 で述べたように Vision Mamba と本研究の最適設計には違いがあり、AuM-Bi-Bi variant は AuM にとって理想的な選択ではない。それでも Table 3 の結果では両モデルは同程度の性能を示す。

著者らは、適切な weight initialization が利用できれば、vision-domain pre-trained weight を用いない場合と同様に AuM が AST を上回る可能性があると考えている。

#### From-scratch audio-only pre-training

ImageNet で pretrain された vision model の weight を用いた AST と AuM の比較に続き、Table 1 の base model を AudioSet で学習した weight を in-domain pre-training として用い、AuM-B と AST-B を初期化する実験も行う。

前節とは異なり、ここで AuM に利用する weight は、AuM とアーキテクチャが完全に同一のモデルから得られている。Table 4 の結果から、in-domain pre-training は両モデルに有効であり、性能を向上させることが分かる。この設定では VoxCeleb を除き AuM が AST を上回る。

## 4. 結論

本研究では、self-attention を使用せず、State Space Model (SSM) のみに基づく初の音声分類アーキテクチャ Audio Mamba (AuM) を提案した。広範な実験により、AuM が計算量・memory usage の両面で高い効率を持ち、確立された Audio Spectrogram Transformer (AST) に対して競争力のある性能を達成することを示した。

入力スペクトログラムを patch 化し、positional embedding を追加し、情報を逐次的に処理するという点で AuM は AST と類似している。一方で、高コストな self-attention を使用しない。この性質から、AuM は汎用的な audio backbone の代替候補となる大きな可能性を持つ。

高コストな self-attention への依存を排除し、長い系列入力を高効率に処理できることから、AuM は将来の音声分野の応用に重要な貢献をもたらすと著者らは考えている。長時間音声を処理する能力は、self-supervised multimodal learning [1, 2, 21] や、in-the-wild data および Automatic Speech Recognition を利用する生成技術の発展に伴って、ますます重要になっている。

さらに AuM は、Audio Masked Auto Encoder [3, 16] のような self-supervised learning、Audio-Visual pretraining [11, 12, 21]、Contrastive Language-Audio Pretraining [24, 29, 30] などの multimodal learning task にも利用できる可能性がある。
